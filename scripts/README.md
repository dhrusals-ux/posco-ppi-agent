# 월간 물가동향 메일 리포트

관심 품목(`data/steel_plant_items.py`)의 최신 지수·전월비·전년동월비를 모아
매월 메일로 발송합니다.

## 왜 GitHub Actions인가

**Streamlit Cloud는 예약 실행을 못 합니다.** 접속이 없으면 앱이 잠들기 때문에
"매월 1일에 스스로 메일 보내기"가 구조적으로 불가능합니다.

GitHub Actions는 레포 안에 있고 무료이며 추가 인프라가 필요 없습니다.
설정 파일은 [.github/workflows/monthly-report.yml](../.github/workflows/monthly-report.yml) 입니다.

## 발송 시점

**매월 25일 09:00 (KST)** 에 실행됩니다.

1일이 아닌 이유: ECOS 생산자물가지수는 **익월 중하순에 발표**됩니다.
1일에 돌리면 아직 신규 발표가 없어 지난달 내용을 그대로 다시 보내게 됩니다.

발표가 갱신되지 않았으면 **발송하지 않습니다.** 같은 내용이 두 번 오면
수신자가 리포트를 신뢰하지 않게 되기 때문입니다. 직전 발송 기준월은 Actions
캐시에 남고, 다음 실행에서 비교합니다.

## 설정 — GitHub Secrets 등록

레포 → **Settings → Secrets and variables → Actions → New repository secret**

| 이름 | 필수 | 설명 |
|---|---|---|
| `ECOS_API_KEY` | ✅ | 한국은행 ECOS 인증키 |
| `SMTP_HOST` | ✅ | 메일 서버 (사내 릴레이 또는 `smtp.gmail.com`) |
| `SMTP_PORT` | | 기본 `587`. `465`면 SSL로 자동 전환 |
| `SMTP_USER` | ✅ | 계정 |
| `SMTP_PASSWORD` | ✅ | 비밀번호 (Gmail이면 **앱 비밀번호**) |
| `SMTP_FROM` | | 보내는 주소. 없으면 `SMTP_USER` 사용 |
| `REPORT_RECIPIENTS` | ✅ | 받는 주소, 쉼표로 구분 |

설정이 빠지면 조용히 넘기지 않고 **명확히 실패**합니다. 어떤 항목이 빠졌는지
로그에 이름이 찍힙니다.

> **사내 메일 서버를 쓰는 편이 낫습니다.** Gmail로 보내면 사내 투자비 관련 정보가
> 외부 메일 서비스를 거칩니다. 정보보안 관점에서 사내 SMTP 릴레이 주소를
> 전산팀에 문의해 쓰시는 걸 권합니다.

## 먼저 시험해 보기 (메일 안 나감)

한 달 기다릴 필요 없습니다. 레포 → **Actions → 월간 물가동향 메일 리포트
→ Run workflow** 를 누르세요.

- `실제로 메일을 발송할지` 를 **false로 두면 미리보기만** 합니다. 기본값이 false입니다.
- 실행이 끝나면 그 페이지 아래 **Artifacts → report-preview** 에서 `preview.html`을
  내려받아 메일이 어떻게 생겼는지 확인할 수 있습니다.
- 내용이 마음에 들면 같은 화면에서 `true`로 바꿔 실제 발송을 시험하세요.

## 로컬에서 실행

```bash
$env:ECOS_API_KEY="키"; .\.venv\Scripts\python.exe -m scripts.send_monthly_report --out preview.html
```

기본은 미리보기입니다. 발송하려면 `--send`를 붙이고 SMTP 환경변수도 넣어야 합니다.

| 옵션 | 설명 |
|---|---|
| (없음) | 미리보기 — 본문을 화면에 출력하고 발송하지 않음 |
| `--out 파일.html` | HTML 미리보기를 파일로 저장 |
| `--send` | 실제 발송 |
| `--force` | 신규 발표가 없어도 발송 (중복 발송 주의) |
| `--threshold 2.0` | '주목할 변동' 기준 전월비 %% (기본 1.0) |

## 리포트 내용

1. **주목할 변동** — 전월비 절대값이 기준(기본 1.0%)을 넘은 품목, 변동 큰 순
2. **관심 품목 현황** — 품목별 지수 · 전월비 · 전년동월비
3. **데이터 품질 고지** — ECOS 품목 매칭에 실패해 빠진 품목을 명시

3번을 넣은 이유: 조용히 빠뜨리면 "관심 품목 24개"라고 적힌 리포트에 실제로는
18개만 담기는 일이 생깁니다. 빠진 게 있으면 리포트가 스스로 알려야 합니다.

매칭 실패가 많으면 `data/steel_plant_items.py`의 `keywords`를 실제 ECOS 품목명에
맞게 보완하세요. 실제 품목명은 앱의 '설비별 PPI 조회' 탭에서 검색할 수 있습니다.

## 알려진 제약

- 전년동월비는 **정확히 12개월 전 같은 달** 데이터가 있을 때만 계산합니다.
  인접 월로 추정하지 않습니다 — 틀린 값을 그럴듯하게 보여주지 않기 위한 것입니다.
  데이터가 없으면 `—`로 표시됩니다.
- 현재는 **설비비(ECOS)만** 담습니다. 공사비(KOSIS)는 발표가 1~2개월 더 지연되어
  같은 리포트에 넣으면 기준 시점이 어긋납니다. 필요하면 별도 섹션으로 분리하는
  방식이 맞습니다.
- 메일 HTML은 인라인 스타일만 씁니다. 대부분의 메일 클라이언트가 `<style>` 태그를
  제거하기 때문입니다.
